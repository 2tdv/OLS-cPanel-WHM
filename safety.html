Safety

Changing a production web server should never be a leap of faith. These are the safeguards built into the switch and into daily operation.

A planned switch

Nothing is switched until you have seen the plan and approved it. The plan lists which sites move to OpenLiteSpeed, which (if any) stay on Apache, which services are affected and how to recover. You can run the switch right away or schedule it in a maintenance window.

Checks site by site

Before the switch, the product records how every site answers under Apache. After it, every site is checked and has to answer as it did before.

Automatic return to Apache

  • A backup and a recovery script are written first.
  • A safety timer is armed: unless the cutover completes, it returns the host to Apache after 45 minutes.
  • Any failed check returns the server to Apache at once.

Hybrid: Apache on standby behind OpenLiteSpeed

Some sites use .htaccess rules or PHP handlers that OpenLiteSpeed cannot reproduce exactly. In the default hybrid profile those sites stay on Apache, which runs in standby behind OpenLiteSpeed on ports 81 and 444, closed to the outside. Visitors still reach everything through OpenLiteSpeed. The product decides this itself, site by site, and the Compatibility view shows why.

The firewall that closes Apache's standby ports is restored at every boot, before Apache and OpenLiteSpeed start, and checked every 15 minutes (release 0.2.5). Updating repairs existing installations by itself.

Account isolation

  • PHP runs as the account user with the account's own group, so one account cannot read another's files.
  • The cPanel plugin runs as the account and can only see that account's own sites.
  • Each account's object cache is a private socket in its own home directory. There is no shared cache.

A small privileged broker

The plugins reach the system through one small privileged component. Its administrator socket is root-only. The account socket identifies the caller from the kernel, never from the request. It offers fixed operations, no shell and bounded requests.

Verified before it changes anything

The installer verifies the signed release and every package digest before installing. See Updates for the key.

Reporting a vulnerability

Please do not open a public issue. Use GitHub's Report a vulnerability form with the affected component, the version, steps to reproduce and the impact. A fix is released before any details are published. Only the latest release receives security fixes. Read the security policy.
