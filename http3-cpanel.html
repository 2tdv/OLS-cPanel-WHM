HTTP/3 (QUIC) on cPanel & WHM with OpenLiteSpeed

Yes, cPanel & WHM can serve HTTP/3 when the web server is OpenLiteSpeed. OLS-cPanel-WHM includes it, and it is on by default. HTTP/3 needs UDP port 443 to be reachable and a valid certificate for each site; on csf and firewalld the installer opens the port for you. This page explains what the installer does about the firewall, how to check HTTP/3 and how to turn it off.

Can cPanel serve HTTP/3?

Yes. OLS-cPanel-WHM runs OpenLiteSpeed, which answers QUIC (the transport under HTTP/3) on the same address and port as HTTPS, but over UDP. Every HTTPS listener has HTTP/3 enabled unless you turn it off (see below), and OpenLiteSpeed tells browsers about it with its own Alt-Svc header, such as h3=":443"; ma=2592000. A browser that supports HTTP/3 can then use it; other clients keep using HTTP/2 or HTTP/1.1 over TCP.

The switch plan that the installer shows before it changes anything contains an HTTP/3 line with the firewall change it would make. See Install OpenLiteSpeed on cPanel & WHM.

What does HTTP/3 need on the server?

  • UDP port 443 open on the server's firewall, next to TCP 443. HTTP/3 does not use TCP.
  • HTTPS with the site's own certificate. A QUIC connection gets its certificate by server name (SNI) exactly as a TLS connection does: the virtual host mapped to that name, and a www. name falls back to the bare name. No extra certificate setup is needed for HTTP/3. LiteSpeed's documentation for its Enterprise edition on cPanel also lists a trusted certificate and an open UDP 443 as the two requirements (LiteSpeed: QUIC and HTTP/3).

What does the installer change in the firewall?

At the switch to OpenLiteSpeed, the installer inspects the host firewall read-only first and shows the change in the plan you approve. After OpenLiteSpeed is serving, it applies only what is missing:

Host firewallWhat the installer doesGoing back to Apache
csfUsed when csf is installed and not disabled. Adds 443 to UDP_IN and UDP6_IN in csf.conf, then runs csf -r. A list or range that already covers 443 is left alone. If UDP_IN does not appear exactly once, nothing is changed and a warning is shown.The original csf.conf is backed up first and put back byte for byte, unless an administrator edited the file since.
firewalldOpens 443/udp in the default zone, for the running state and the permanent configuration, only where it is missing. It never runs a global reload.Removes exactly the port state it added; ports you opened yourself stay.
nftables or another firewallNothing: other firewall tables are never edited. If an input hook drops traffic and no rule mentions UDP 443, the installer shows a warning instead.Nothing to undo.

The firewall step never makes the switch fail. If it fails, the partial change is undone and the outcome lists a warning. See Safety for how the switch and the way back to Apache work.

The product only looks at csf, firewalld and nftables on the server itself. A firewall outside the server, such as a network firewall at your provider, is not changed, so UDP 443 has to be allowed there by you.

How do I check that HTTP/3 works?

  1. Run ols-cpanel http3 status as root. It shows whether HTTP/3 is enabled, what the firewall inspection found for UDP 443 (read-only), and for each site the share of requests served over HTTP/1.x, HTTP/2 and HTTP/3 in its recent access log. The access log request line ends in HTTP/3 for these requests.
  2. Ask for the headers of an HTTPS page and look for alt-svc containing h3: curl -sI https://example.com/ | grep -i alt-svc. OpenLiteSpeed adds the header; the product adds none of its own.

The header only shows that HTTP/3 is offered. The share in ols-cpanel http3 status shows that visitors are actually connecting over HTTP/3. Site owners can also run the Speed check in the cPanel plugin, which reports whether a site is compressed, cached, offered over the fastest connection and has a valid certificate.

Why is HTTP/3 not used on my site?

  • UDP 443 is blocked, on the server or in a firewall in front of it; visitors are then served over HTTP/2 or HTTP/1.1. Look at the firewall line of ols-cpanel http3 status.
  • The site is one that Apache keeps serving behind OpenLiteSpeed: OpenLiteSpeed does not add the header behind a proxy.
  • HTTP/3 was turned off on purpose (next section).
  • HTTP/3 was enabled after a switch that was done with it turned off. Enabling it later does not open the firewall; open UDP 443 yourself. ols-cpanel http3 status shows what the product would change.
  • The site has no valid certificate for the name visitors use.

How do I turn HTTP/3 off?

Create /var/lib/ols-cpanel/http3.json as root, not writable by group or others, with {"enabled": false}. OpenLiteSpeed then creates no QUIC engine and no UDP socket and sends no Alt-Svc header, and the switch touches no firewall. Use it where UDP 443 cannot be reached, so browsers are not offered HTTP/3 they cannot use.

The file is read at every configuration build, so a change takes effect at the next reconcile pass. On a running server, systemctl restart ols-cpanel applies it to the QUIC engine. The file must be at most 4096 bytes and not a symbolic link, and it accepts only the key enabled with true or false. Anything else (another key, another value, invalid JSON, or a file writable by group or others) stops install --prepare, the switch and every reconcile pass until the file is fixed. Changing the file after install --prepare makes a plan you have not approved yet out of date, so prepare again. A missing file, {} and {"enabled": true} all mean enabled.
