LSCache on cPanel without a LiteSpeed Enterprise license

You can run LSCache page caching on cPanel & WHM without buying LiteSpeed Enterprise by using OpenLiteSpeed, LiteSpeed's free edition, through the free GPLv3 project OLS-cPanel-WHM. Site owners clear the cache from cPanel, administrators from WHM or the command line, and an hourly cleanup keeps the cache within size limits. This page covers which applications get the cache, how clearing and cleanup work, and where the limits are.

Why does LSCache normally mean LiteSpeed Enterprise on cPanel?

LSCache is the page cache built into LiteSpeed web servers. The cache features of LiteSpeed Cache for WordPress need a LiteSpeed server: according to LiteSpeed's LSCache for WordPress FAQ, the plugin's caching needs one of its LiteSpeed products, namely LiteSpeed Web Server, OpenLiteSpeed (v1.4.17 or later), LiteSpeed Web ADC or QUIC.cloud CDN. Apache is not one of them, so adding LSCache to a cPanel server running Apache has meant moving to a LiteSpeed server, and LiteSpeed Web Server (Enterprise) is the commercial one.

OpenLiteSpeed is the free, open-source edition, and OLS-cPanel-WHM is what connects it to cPanel & WHM. It is an independent project, not made by or affiliated with LiteSpeed Technologies or cPanel, L.L.C.; see Is OLS-cPanel-WHM made by LiteSpeed or cPanel?

How does OLS-cPanel-WHM provide LSCache on cPanel?

OLS-cPanel-WHM replaces Apache with OpenLiteSpeed as the web server for the cPanel sites, while cPanel & WHM stay in place. Because the server is OpenLiteSpeed, the LiteSpeed Cache plugin of your application can store and serve pages. In the project's nine-day test on 25 sites, OpenLiteSpeed served cached pages of WordPress, Joomla, Drupal and Laravel without running PHP; see the test results.

  • WordPress, Joomla, Drupal, Laravel. Joomla, Drupal and Laravel sites are served by OpenLiteSpeed because the installer translates their stock .htaccess files (release 0.2.11; before that they stayed on Apache without the page cache). Drupal sites with LiteSpeed Cache stay on OpenLiteSpeed because the PHP setting the module writes for LiteSpeed is applied to that directory's PHP (release 0.2.12). See the changelog.
  • Turning it on for a site. OLS-cPanel-WHM does not install the LiteSpeed Cache plugin and never changes a site's code or plugins. The site owner installs the free plugin, for example LiteSpeed Cache for WordPress, and the settings are the plugin's own. If WordPress LiteSpeed Cache is active, the product connects it to the account's private object cache automatically; see the object cache page.
  • Sites that stay on Apache. A site whose .htaccess rules OpenLiteSpeed cannot run stays on Apache behind OpenLiteSpeed, and that site has no page cache store of its own. See Safety and the FAQ.

How do I clear the page cache?

  • Site owners use the cPanel plugin Website performance (OpenLiteSpeed). Its Page cache view shows how much is stored and has a button to clear the cache for one site or all of them (Page cache), and the one-click Clear cache icon on the cPanel home clears all of an account's sites at once (Clear cache).
  • Administrators have a page cache view in WHM, and as root they can run ols-cpanel cache stats for the entries and bytes per site, and ols-cpanel cache purge with --all, --account=USER or --domain=DOMAIN to empty the cache of the server, one account or one domain.
  • Automatically: an hourly cleanup removes old entries and keeps each site's cache and the whole server's cache under size limits. The defaults are 512 MB per site and 10% of the cache filesystem (at most 20 GB) for the server, and the administrator can change them in the WHM page cache view or with ols-cpanel cache limits.
  • The cache is emptied at every switch between Apache and OpenLiteSpeed, so pages from before a return to Apache are never shown (release 0.2.13).

What does LSCache on OpenLiteSpeed not do?

  • Logged-in visitors. In the project's test, pages for logged-in visitors were not served from the page cache, so a large shop with many logged-in customers sees a smaller gain; see the limits on the test results page.
  • Some LSCache features may be missing. LiteSpeed's FAQ says LiteSpeed Cache for WordPress can work well with OpenLiteSpeed, although some features, such as ESI, may not be supported.

What did it change on the test server?

The project compared a full day of cPanel's Apache with a full day of OpenLiteSpeed on the same 25 sites, within a test with nine days of traffic. The object cache ran on both days, so the differences come from the web server, PHP and the page cache. The numbers are on the test results page; they are not repeated here, because they describe that test server only.
